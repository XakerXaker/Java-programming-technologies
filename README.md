# Java Programming Technologies

Проект представляет собой серию из пяти последовательных лабораторных работ, в ходе которых поэтапно разрабатывается полноценная система управления питомцами (котиками) и их владельцами — от консольного приложения до микросервисной архитектуры с брокером сообщений.

## Структура проекта

```
├── FirstLab/       — ЛР-1: Банкомат, CI/CD
├── SecondLab/      — ЛР-2: ORM, JPA, Hibernate
├── ThirdLab/       — ЛР-3: Spring Boot, REST API
├── FourthLab/      — ЛР-4: Spring Security
├── FifthLab/       — ЛР-5: Микросервисы, JMS
└── Statements/     — Условия лабораторных работ
```

## Обзор лабораторных работ

### Лабораторная 1 — Банкомат & CI
**Тема:** Основы Java, системы сборки, JavaDoc, JUnit  

Консольное приложение, имитирующее работу банкомата: создание счёта, просмотр баланса, снятие/пополнение, история операций. Настройка CI через GitHub Actions. Без Spring — чистая Java + Maven/Gradle.

---

### Лабораторная 2 — ORM & Data Layer
**Тема:** JDBC, JPA, Hibernate, Controller-Service-DAO  

Проектирование модели данных: сущности **Питомец** (имя, дата рождения, порода, цвет, хозяин, друзья) и **Владелец** (имя, дата рождения, список питомцев). Реализация CRUD-операций через Hibernate ORM с PostgreSQL. Миграции БД. Тестирование через JUnit + Mockito/TestContainers. Без Spring.

---

### Лабораторная 3 — Spring Boot REST API
**Тема:** Spring MVC, Spring Boot, Spring Data JPA  

Веб-приложение с REST API для управления котиками и их владельцами. DTO вместо JPA-сущностей, пагинация и фильтрация результатов, `CrudRepository`. Тестирование через MockMVC. Опционально — Swagger-документация.

---

### Лабораторная 4 — Spring Security
**Тема:** Аутентификация, авторизация, ролевая модель  

Расширение приложения из ЛР-3: ролевая модель (администратор / пользователь-владелец), `SecurityFilterChain` (Spring Security 6.x), хеширование паролей. Владелец может изменять только своих питомцев — иначе HTTP 403. Опционально — JWT-аутентификация, Swagger UI с авторизацией.

---

### Лабораторная 5 — Микросервисная архитектура
**Тема:** Spring AMQP, JMS, RabbitMQ / Kafka, микросервисы  

Декомпозиция монолита на **три** независимых приложения:
- **Микросервис питомцев** — управление котиками (своя БД)
- **Микросервис владельцев** — управление владельцами (своя БД)
- **HTTP Web-Gateway** — приём HTTP-запросов, аутентификация, маршрутизация через брокер сообщений

Взаимодействие через **RabbitMQ** или **Kafka**. Контракт REST API для конечного пользователя не меняется.
